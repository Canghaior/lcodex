# 产品方案补充建议评审

日期：2026 年 10 月 19 日。评审基线为本轮读取的四份仓库文档，结果已纳入开发方案 0.2。工作目录只有文档，未见应用工程或 `.git` 元数据。本轮没有搭建工程、安装依赖、启动 app-server 或执行模型 API 测试。

结论：这批建议主要补齐原有功能的行为和验收口径，适合保留 P0 至 P4 结构后纳入。需要控制范围的是文件恢复及改动生效方式，不能把它们当作小补充直接承诺；Windows 保护能力和引擎控制点应前移到 P1。

## 官方资料核对与影响

以下为文档事实或现场版本观察，不是本项目功能通过证据。资料查询日期均为 2026 年 10 月 19 日。

| 来源 | 核对结果 | 对方案的影响 |
| --- | --- | --- |
| [Codex app-server](https://learn.chatgpt.com/docs/app-server) | 官方提供版本相关 schema 生成方式、读取或恢复会话与中断接口；中断请求和最终 turn 状态分开 | 固定版本后生成 schema；重连查事实，停止请求返回不能当作进程已终止 |
| [Codex 接口兼容要求](https://learn.chatgpt.com/docs/enterprise/gateway-compatibility) | 需验证 Responses、增量流、历史、工具结果与错误；单次聊天或模型列表不证明工具循环正常 | P1 拆成 A 协议、B 任务、C 本地执行，不仅验证连接 |
| [DeepSeek Responses 接口参考](https://api-docs.deepseek.com/api/create-response/) | 已读取页面正文：无状态对话需要客户端历史；developer 按 user 解释；工具结果关联 call_id；流有完成、未完成和失败终态 | 检查实际历史与角色映射、编辑工具和终态；不能把同名字段视为同等语义 |
| [DeepSeek Responses 中文指南](https://api-docs.deepseek.com/zh-cn/guides/responses_api/) | 直接打开未成功；官方页面的搜索索引正文列出 max_tool_calls、parallel_tool_calls 被忽略，服务端上下文管理等不支持，custom 工具仅支持 apply_patch | 将计数、串行调度、上下文和工具集列为待复核项；P1 获取正文及实测后再冻结配置，不仅凭索引保证兼容 |
| [Windows 沙箱](https://learn.chatgpt.com/docs/windows/windows-sandbox) | 当前正文区分 mxc、elevated、unelevated；后者不支持拒绝读取路径。MXC 单命令测试示例注明 CLI 0.162.0 起，且受 Windows 能力约束；拒读匹配时机也存在限制 | 不能按新文档断言本机旧版支持；验证真实生效方式、动态文件、进程退出和拒读能力；不静默选择较弱隔离 |

本机查询 `codex --version` 返回 `codex-cli 0.140.0`，退出码为 0，同时出现临时目录清理与 PATH alias 创建访问拒绝警告。没有为排除警告修改系统，也没有运行 sandbox 或 app-server。这只证明命令能报告版本；项目采用的版本和配置未冻结。

## 重大待决定事项

完整选项与影响见开发方案 D01 至 D05。当前无需为文档完善决定引擎重写或安装软件。

- D01：直接落盘与审阅后应用，P1 给出保护和成本证据后、P2 前决定。
- D02：最近任务文件恢复是否纳入首版，先做可行性结论，不提前承诺。
- D03：只有原生 Windows 不满足要求时才决定是否接受 WSL 的额外部署与路径成本。
- D04：真实 API 验证前确定费用额度；本轮没有付费请求。
- D05：只有 P1 暴露保护或项目支持阻塞时，才决定适配或缩减范围。
