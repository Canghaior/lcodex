# lcodex 0.0.1 候选版使用说明

本候选面向 Windows x64 上的小型单包 JavaScript / TypeScript 项目，默认使用 DeepSeek V4 Pro 高强度思考模式（`deepseek-v4-pro`，`reasoning.effort=high`）。当前开发机上的验证不等于所有 Windows 电脑均已验证；阶段证据和未完成项见 [分发验证](validation/P4_PACKAGING.md)与[思考模式验证](validation/P4_THINKING.md)。

## 第一次使用

本机体验也可以直接运行仓库中的 `.local/releases/win-unpacked/lcodex.exe`，无需先安装；如果窗口已经打开，直接从第 2 步设置。首次体验样本在 `.local/demo-project`，该目录的 README 提供了任务示例和测试命令。

1. 运行本地 `lcodex-0.0.1-win-x64-setup.exe`，选择安装位置。当前包未签名；核对来源和对应 SHA-256，不需要关闭 Windows 安全防护。应用自带 Codex、PowerShell 和 Node，无需为应用另装这些运行时。
2. 打开左下角“设置”，保存自己的 DeepSeek API Key。密钥由 Windows 加密，保存后不回显。聊天和任务使用的代码、工具结果会经 DeepSeek 官方 API 发送；命令和文件操作在本机执行。
3. 设置累计预算和单任务预算，打开官方价格页，核对与界面记录一致后确认。每日首次请求需要当日价格确认；由旧 Flash 候选升级后也要重新核对 Pro 价格。价格不同请停止调用并更新价格配置实现，不能直接确认旧价格。模型连接验证会发出一次计费请求，单纯保存设置不会。
4. 选择项目文件夹。Git 不是必需条件；已有改动会保留。项目不能与应用数据目录相互包含，应用也不会自动初始化、提交或推送用户项目的 Git。
5. 在项目设置中填写已准备好的验证命令，例如 `npm.cmd test; exit $LASTEXITCODE`。项目依赖由用户准备；应用不会自行联网安装依赖。任务中的命令不能访问网络，包括本机网络服务；需要数据库或服务连接的检查应在任务外另行执行。没有配置验证命令时，任务整体保持“尚未验证”，工具记录仍可查看。
6. 首先用“只读分析”了解代码。需要修复或实现小功能时切换“修改并验证”，描述目标、复现方式和验收要求。执行中的工具输出在任务记录及右侧输出区查看。
7. 任务结束后打开“改动”，核对文件差异、实际验证和未完成事项，再点击“应用全部”。应用前原项目保持不变；出现并发编辑或归属不明时会拒绝覆盖。应用完成后仍建议按自己的实际运行场景检查。

## 范围和限制

- 源码与只读资源合计 16 MiB、单文件 1 MiB、目录项最多 1024；普通预装依赖合计 64 MiB、单文件 16 MiB、目录项最多 8192。链接型依赖、多包、大型工程和其他语言运行环境尚未验证。
- 项目中的第三方依赖和二进制资源在副本中只读。模型命令没有网络、提权或原项目写入权限；依赖缺失时应在任务外准备后重新开始。
- 每任务最多 8 次模型请求，最后一次用于总结已有结果；最多 12 次工具调用、8 轮工具。工具容量先用尽时，下一次请求只允许总结，仍受原请求、费用和时间上限约束。连续两次工具失败会停止；命令最长 45 秒，任务最长 180 秒。达到限制保留结果，不自动重试或申请更大权限；正常结束并给出总结不等于所有要求已完成，应查看未完成事项和验证结果。
- 已配置验证命令的修改任务会为最后一次工具机会保留验证；命令失败或未运行时不会显示通过。后续工具操作会使先前验证失效，需要重新检查。输出中出现工具标记不代表命令实际执行，实际工具记录才是执行依据。
- 每次发送的完整请求最多 96 KiB，包含工具定义、历史、思考内容和工具输出；输出最多 8192 tokens，思考与最终答复共同占用。项目容量上限不代表可以一次发送整个项目。输入超限时保留记录并停止，可在新聊天中缩小问题、要求只读必要片段；不会自动丢弃旧上下文后继续。
- 每次命令输出最多 1024 tokens；分析大文件时按函数和短行段读取，避免整文件输出及重复读取。费用预留包含下一次可能消耗，因此累积的代码和工具输出较大时，可能在实际估算消耗达到金额上限前停止。
- “首次验证退出码”指本轮首次识别到的、与项目配置完全匹配的验证命令；工具中更早的组合命令仍可查阅，不把该字段当作独立的任务前基线。修改后的命令通过也不代表覆盖所有功能。
- 费用是按已确认价格计算的保守估算；未知用量、在途预留和实际账单不同。Pro 思考模式比旧 Flash 配置单价高；思考 tokens 已包含在输出用量中，不重复计算。请求前按本次输入和完整输出上限预留费用，剩余预算不足以覆盖预留时会停止，即使已发生消耗尚未达到上限。不会自动关闭思考、换回 Flash 或提高预算。
- 删除聊天、修改预算上限都不会清零已发生消耗。遇到未知预留时先核对，界面明确全额计入后才能继续。
- 只能同时执行一个任务，同项目待审阅或待核对的写任务需先处理。首版没有一键撤回、复杂 Git 工作流或多模型切换。

## 停止、恢复与删除

点击停止后先阻止新操作，再核对进程与引擎终态。状态显示“需要核对”时不要将其当作已经安全完成，也不要删除记录解除项目锁。

引擎偶发退出超时时，应用会回收本任务的进程组，并在条件允许时只读核对保存的结果；这个收尾可能需要额外等待。不会因此追加模型请求、自动重试命令或应用文件。无法确认进程结束或结果一致时仍显示“需要核对”。

正常关闭后的聊天可以恢复；待应用改动需点击“核对并重开审阅”，不会自动执行模型或应用文件。已经向原项目应用的文件改动，不会因停止或删除聊天而撤回。对于可以证明从未应用、引擎已退出的隔离尝试，界面提供明确放弃操作；极早中断且缺少可读历史时仍需保留核对。

发布版默认数据目录为 `%APPDATA%\lcodex`；开发窗口的数据在仓库 `.local/desktop`。密钥、聊天、引擎历史、预算和未决恢复记录都属于应用数据。通过界面删除已结束聊天及密钥；未决记录不能作为缓存删除。删除本地记录不能撤回已经发送至模型的数据。卸载和文件恢复是不同操作，不应手动清空数据目录来处理异常。
