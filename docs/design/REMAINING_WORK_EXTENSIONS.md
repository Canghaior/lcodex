## 1. 范围、约束与分期原则

本文件覆盖待办 B25–B34。章节编号保持与总览一致；实施工作包使用 X25A、X25B 等编号。这里的服务名、数据字段和接口职责是设计建议，不表示已有实现。

用户确认架构方案后，仍需另行明确开始开发的时间和工作包。B25–B34 属于后续扩展，逐项确定范围；不能把本次设计要求、既有开发授权或某一个扩展的批准解释为全部扩展的实施授权。普通实现细节在获批工作包内自行处理；改变执行权限、支持范围、成本或主要交互时重新形成具体决定。

当前 P4 尚未整体通过，默认 AppData 运行、复杂源码任务、最终安装包与干净 Windows 验收等仍需按总览收口。扩展不得替代这些退出条件。当前首版边界继续有效：Windows、已验证的小型单包 JS/TS 项目、两家固定厂商、隔离副本执行、审阅后受控应用、同项目单写、凭据仅本机保存、未知用量不记零。

统一遵守以下规则：

1. renderer 只通过允许的 IPC 请求业务操作，不获得凭据、任意文件写入或任意 shell 权限。执行与授权在后台落实，不能依赖提示词或工作目录。
2. 所有新增写能力沿用基线、冲突检测、受控应用和持久化操作记录；停止、恢复聊天、恢复文件分别表达、分别验收。
3. 恢复和重试不自动重放已经执行或执行结果不明的命令、文件操作及外部副作用。
4. 新增模型、平台、语言或连接器须有自己的兼容与真实行为证据，不能继承原范围的通过结论。
5. 不为后置功能提前搭建完整插件框架。先在获批场景中形成稳定职责，再提取可复用接口。
6. 新试验额度、云服务、签名及分发等成本全部待决；不挪用、重置旧账本，不复用一次性额度。

## 2. B25：最近任务撤回、逐块撤销与长期历史

### 现状与目标

D02 已明确首版后置一键撤回；当前基线、差异、冲突检测及未决应用记录不等于提供撤回功能。先解决一次可归属的已应用任务恢复，再讨论逐块撤销和长期版本浏览。

### 模块、数据与流程

- `RestoreService` 接收明确的任务与文件选择，读取不可变 `ApplyReceipt`。回执至少包含任务 ID、项目身份、规范化相对路径、变更类型、应用前后内容引用及哈希、每文件结果和回执版本。
- 内容由 `SnapshotStore` 保存；应用日志、有效恢复操作和未决状态引用的内容不得被历史清理删除。引用归属及过期策略由后台统一管理。
- 用户发起恢复后，先展示新增/修改/删除文件的恢复预览和冲突项；后台重新核对项目身份、路径边界及当前内容是否等于原任务应用后的内容。
- 满足条件的文件经现有受控应用通道恢复。先记录恢复意图，再逐文件记录结果；文件替换可原子化，但不宣称跨文件事务天然原子。崩溃后根据日志和实际哈希核对，不能直接补写“已恢复”。

### 拆期与依赖

| 工作包 | 范围 | 依赖及输出 |
| --- | --- | --- |
| X25A | 最近一次已应用任务的整文件撤回 | 变更 D02；应用回执、基线和未决恢复可靠；输出恢复预览、冲突报告及部分结果 |
| X25B | 用户选择文件及文本块撤销 | X25A；稳定的块归属与上下文匹配；只支持已验证文本类型；现有二进制只读限制保持，新增可写二进制须另行验证 |
| X25C | 长期版本历史与跨任务恢复 | X25A、容量与保留策略；输出版本索引、保留设置和可恢复范围提示 |

### 验收、失败处理与范围决定

覆盖新增/修改/删除、用户后续编辑、任务间连续修改、路径变为链接、文件缺失、恢复中断、磁盘不足及部分成功。用户后续内容不匹配时不得覆盖；恢复失败保留可核对记录。不得使用 Git reset、clean 或索引变更代替恢复保护。需决定恢复窗口、保留容量、是否保留删除文件内容，以及 X25B/X25C 是否纳入；不能把 X25A 宣称为任意历史回退。

## 3. B26：大项目、多包与更多语言

### 现状与目标

当前写任务支持范围受 D05 限定，不能因为可打开或搜索更多文件就宣布支持其构建和修改。扩展以具体项目类型及规模档位为单位，保留可拒绝的边界。

### 模块、数据与流程

- `ProjectProfile` 描述语言、工作区/包结构、项目根、依赖来源、测试命令和配置来源；`WorkspacePlan` 冻结本次任务的源码集合、只读依赖、子包关系、资源上限和排除项。
- 诊断先判断环境、依赖及命令是否可用，再生成复制计划；用户确认存在歧义的入口后执行。搜索、上下文选择、复制和允许写入范围使用同一计划，避免各模块理解不同的项目边界。
- `LanguageAdapter` 只提供经过验证的识别、命令建议和诊断规则，不自行安装工具链或扩大执行权限。复制策略按实测优化，保持原项目不可被工具提前写入。
- 链接依赖、符号链接和目录联接单独定义身份与归属规则；未知链接默认不进入写任务，不能只按字符串前缀判断范围。

### 拆期与依赖

| 工作包 | 范围 | 依赖及输出 |
| --- | --- | --- |
| X26A | 更大规模的单包 JS/TS | 项目诊断、配置与命令发现；输出按样本验证的资源档位，不直接移除限制 |
| X26B | 多包 JS/TS 与明确依赖关系 | X26A；输出子包选择、工作目录及跨包验证规则 |
| X26C | 按用户真实需求逐语言扩展 | 每种语言独立工作包、工具链和样本；输出已验证语言/框架矩阵 |

### 验收、失败处理与范围决定

覆盖遗漏文件、错误依赖、嵌套根、链接越界、大小写/路径异常、任务中外部编辑、耗时、磁盘和费用边界。独立核对实际测试入口、数量和结果；超出范围时明确拒绝或仅开放已验证的阅读能力。需决定首个目标项目类型、规模及新语言顺序；每次扩大范围更新 D05 与验收矩阵。

## 4. B27：macOS 与 Linux

### 现状与目标

当前 Windows 的进程、文件保护和密钥保存实现不具备自动跨平台等价性。保持桌面业务与 UI，逐平台验证执行层。

### 模块、数据与流程

- `PlatformRuntime` 承担路径身份、受控文件应用、进程归属/停止、密钥存储、沙箱启动、运行时发现和安装路径；Windows 现有行为作为首个适配实现。
- `PlatformCapabilities` 明确已验证能力及限制，后台按能力拒绝无法保护的任务，不静默退回无隔离执行。
- 平台配置、凭据引用、运行时版本与沙箱策略写入任务身份和诊断。业务层使用统一事件与结果，但平台特有故障保留具体原因。

### 拆期与依赖

| 工作包 | 范围 | 依赖及输出 |
| --- | --- | --- |
| X27A | 用户选择的一个平台可行性验证 | 固定目标系统与引擎版本；给出保护能力及不可行点，不预先承诺写任务 |
| X27B | 该平台受限项目的完整闭环 | X27A 证明执行边界；完成密钥、修改、停止和恢复 |
| X27C | 安装、打包与目标系统验收 | X27B；形成独立支持矩阵和候选包证据 |

### 验收、失败处理与范围决定

分别核对 shell 子进程、取消后残留、文件权限、路径语义、密钥存储不可用、应用中断及干净系统安装。操作系统机制和依赖能力在实施前查官方资料并实际验证。需决定先支持哪个平台、系统版本范围及设备/虚拟机资源；未通过保护门槛不得开放写入，不能用提示词或 cwd 代替系统约束。

## 5. B28：多任务与多 Agent

### 现状与目标

目前全局单任务，同项目单写约束仍须保留。先增加可解释的队列，再开放不同项目的有限并行；多 Agent 是后续独立能力。

### 模块、数据与流程

- `TaskScheduler` 管理任务状态、项目身份、队列、全局并发额度、项目写锁和取消树；每个任务拥有隔离副本、预算预留、事件流及审阅结果。
- 项目身份以实际路径和已验证的别名识别规则确定，不能通过不同路径字符串绕过单写约束。进程重启先核对未决任务，不能单凭租约时间到期释放写锁。
- 调度前原子检查并发、预算和项目权限；一个任务停止不影响其他项目，但父任务停止必须阻止全部子任务继续派发。
- 多 Agent 通过受控消息与不可变成果引用协作。工作者提交分析或补丁，主任务统一决定工具执行、验证与应用；子任务不获得父任务没有的能力，不共享可变工作副本。

### 拆期与依赖

| 工作包 | 范围 | 依赖及输出 |
| --- | --- | --- |
| X28A | 多任务排队 | 稳定的任务状态与恢复；队列取消和可见资源等待原因 |
| X28B | 不同项目有限并行 | X28A；并发预算预留、资源配额、隔离事件和独立停止 |
| X28C | 一个主任务的多 Agent 协作 | X28B 及子任务归属记录；统一计划、结果核验和冲突审阅 |

### 验收、失败处理与范围决定

覆盖两个路径指向同项目、同时申请写锁、并发触顶、模型在途请求、父子停止、单子任务崩溃、迟到事件、补丁冲突及重启。未知用量保留预留；子任务失败不自动重放已执行操作。需决定并发上限、计费展示和子任务可执行能力；不同项目并行不代表允许同项目多写或自动合并补丁。

## 6. B29：MCP、Skills、插件与市场

### 现状与目标

当前无面向任意第三方的产品扩展承诺。MCP 连接、Skills 指引、可执行插件和插件市场属于不同信任边界，应分别交付。

### 模块、数据与流程

- `ToolRegistry` 保存工具身份、来源、版本、输入结构及声明能力；`CapabilityBroker` 在执行层核验项目范围、网络目标、凭据引用和读写能力。
- 调用记录绑定工具版本、授权决定、操作 ID、超时和结果；撤销连接后阻止新调用，在途动作按实际状态核对。
- MCP 适配器只连接已配置服务；协议版本和固定引擎能力在实施时核对。工具说明及返回内容均为不可信数据，不能改变权限。
- Skills 作为版本化工作指引加载，显示来源与生效范围，不把自然语言指令解释成授权。可执行插件使用受控独立进程及资源上限；插件市场另有发布身份、完整性、升级和撤销机制。

### 拆期与依赖

| 工作包 | 范围 | 依赖及输出 |
| --- | --- | --- |
| X29A | 少量固定、只读 MCP 连接 | 统一工具策略；来源和数据外发边界可见 |
| X29B | 明确授权的外部写工具 | X29A；副作用分类、确认与不明结果核对 |
| X29C | 本地 Skills | 来源、版本、启停和冲突优先级规则；不得扩权 |
| X29D | 第三方可执行插件 | X29A/B；独立运行、能力声明、撤销和升级验证 |
| X29E | 插件市场 | X29D；发布治理、分发成本、下架与恶意版本处置 |

### 验收、失败处理与范围决定

覆盖恶意说明、参数注入、越界读取、秘密外传、进程超时、连接撤销及插件升级后能力变化。插件安装不等于批准全部能力；连接失败不回退到任意 shell。需决定初始连接器、可写动作、第三方分发责任和维护范围，不能把 MCP 支持宣传为完整市场已具备。

## 7. B30：浏览器与电脑自动化

### 现状与目标

当前项目文件沙箱不覆盖网站账号、浏览器会话或桌面操作的外部副作用。新增自动化需要独立授权与会话边界。

### 模块、数据与流程

- `InteractiveSession` 绑定目标浏览器/应用、会话身份、站点范围、允许动作和停止规则；模型只接收当前任务需要的数据。
- `ActionJournal` 保存动作 ID、目标、执行前确认、派发状态及结果证据；不能因为页面未返回就重新点击提交。
- `AutomationPolicy` 区分只读、可逆修改和发送/支付/权限变化等外部副作用，结合用户明确授权决定是否需要再次确认。
- 页面、截图、剪贴板和登录状态有独立脱敏及保存策略；登录凭据不写入模型上下文、普通日志或任务快照。控制失焦、目标变化或人工接管时立即停止派发。

### 拆期与依赖

| 工作包 | 范围 | 依赖及输出 |
| --- | --- | --- |
| X30A | 浏览器只读获取 | 明确站点和数据边界；独立会话与来源说明 |
| X30B | 有限表单/网页写操作 | X30A；动作授权、外部结果核对及不可重放规则 |
| X30C | 桌面应用自动化 | 独立平台权限验证；目标窗口、人工接管和状态变化防护 |

### 验收、失败处理与范围决定

覆盖页面变化、弹窗、失焦、登录失效、提示注入、执行中断、超时后结果未知和用户手动操作。停止仅承诺不再派发，已经提交到外部服务的动作必须核对，不声称能自动撤销。需决定允许应用/站点及动作，账号与敏感场景单独评审。

## 8. B31：更多厂商与模型

### 现状与目标

当前仅支持已明确授权的 DeepSeek 与 OpenAI 固定配置。新增模型不能只增加一个下拉选项；协议、工具行为、计量和恢复身份必须一起验证。

### 模块、数据与流程

- `ProviderProfile` 包含厂商/端点/模型身份、协议适配版本、能力限制、上下文与输出上限、用量字段、价格版本和币种。新型号及价格由实施时官方资料与实际账号能力确定，本方案不预填。
- 适配器输出统一消息、工具、拒绝、终止及错误事件；后台负责参数校验、能力限制、密钥引用和预算预留。
- 每个聊天和任务持久化完整配置身份；恢复核对一致性。切换厂商默认新建聊天，不自动转发既有历史，不自动降级为其他模型。
- 凭据分厂商保存，账本按授权域和币种隔离。未知用量、重试及在途请求均有明确账务状态。

### 拆期与依赖

| 工作包 | 范围 | 依赖及输出 |
| --- | --- | --- |
| X31A | 一项明确的新厂商/模型验证 | 用户选择目标；官方事实核对与协议模拟矩阵 |
| X31B | 同一目标真实能力与桌面集成 | X31A、独立试验额度；三类任务和异常路径记录 |
| X31C | 多个已验证配置的选择与维护 | 已有多个通过实例；配置迁移、旧聊天兼容及下线规则 |

### 验收、失败处理与范围决定

覆盖完整/截断响应、拒绝、工具参数、流事件顺序、网络异常、限流、用量缺失及恢复身份不匹配。不能用连接成功代替工具任务通过；不得自动跨厂商重试。需决定目标厂商、模型、端点、价格来源和新预算；任意代理地址与动态模型路由不默认纳入。

## 9. B32：账号、云同步与多端

### 现状与目标

当前优先本地个人使用。增加云服务涉及持续运营、数据边界和多端冲突，不能简单上传本地数据目录。

### 模块、数据与流程

- 保持离线可用；`SyncRecord` 使用稳定 ID、记录版本、设备 ID、删除标记和内容引用。同步仅处理用户显式选择的数据类别。
- `SyncCoordinator` 先拉取并核对版本，再合并或形成冲突分支，保留用户可判断的来源；删除标记按明确保留规则传播，避免离线设备重新上传已删除记录。
- API Key 保持设备绑定；进程 ID、锁、执行中的命令、路径授权和未决应用不能跨设备恢复成可执行状态。新设备重新配置凭据和项目权限。
- 若希望多端共享预算，必须设计服务器端不可覆盖的预留与结算协议；未完成前不把本地账本文件同步当作统一预算控制。

### 拆期与依赖

| 工作包 | 范围 | 依赖及输出 |
| --- | --- | --- |
| X32A | 数据边界、威胁模型与服务方案 | 决定运营主体、费用、加密与账号恢复；不给出已上线承诺 |
| X32B | 用户选择的非敏感设置同步 | X32A；版本化存储、冲突和设备撤销 |
| X32C | 可选对话同步 | X32B；正文/附件的数据规则、删除语义和容量计费 |
| X32D | 跨设备统一预算等进一步能力 | 单独立项；不能继承本地预算的安全结论 |

### 验收、失败处理与范围决定

覆盖离线重连、双端编辑、删除冲突、账号失效、设备撤销、版本迁移和部分上传。同步失败不阻断本地已有数据；不能宣称本地删除撤回了模型厂商已收到的数据。需决定数据类别、加密与密钥恢复的取舍、保存地区、容量和持续费用。

## 10. B33：Git 工作流与完整 IDE

### 现状与目标

当前保留用户 Git 初始状态，并不等于提供提交、推送和分支管理。开发本仓库时的 GitHub 推送授权与产品操作用户项目的权限不同。完整 IDE 是更大的产品方向，单独立项。

### 模块、数据与流程

- `GitService` 先提供只读 status/log/diff。写操作计划绑定仓库身份、HEAD、索引状态、工作区状态、目标分支及明确文件清单。
- 用户审阅后后台再次校验状态，执行被授权的暂存/提交/推送操作并记录结果；检测外部 Git 修改时停止并重新展示差异。
- 已有暂存和未暂存内容分别展示，不能自动把用户全部修改加入提交。合并产生冲突时提供真实状态和手工处理入口，不自动 reset、clean 或强推。
- 编辑器、语言服务、调试器和终端若纳入 IDE，分别明确运行位置、资源与权限；不能让任意终端绕开当前原项目写入边界。若改变 D01，须先形成新的具体范围决定。

### 拆期与依赖

| 工作包 | 范围 | 依赖及输出 |
| --- | --- | --- |
| X33A | 只读 Git 状态、历史与差异 | 项目身份与 UI 搜索；清楚区分已有改动和任务改动 |
| X33B | 显式提交与推送 | X33A；精确文件审阅、认证和远程结果核对 |
| X33C | 分支与合并 | X33B；索引、冲突及外部并发修改保护 |
| X33D | 完整 IDE 可行性与独立规划 | 用户明确产品目标；重新评审编辑/执行边界及长期维护成本 |

### 验收、失败处理与范围决定

覆盖已有暂存、未跟踪文件、外部索引变化、分支变化、提交失败、远程拒绝及推送超时后结果未知。推送结果未知时先读取远端核对，不盲目重复操作。需决定可操作的 Git 动作、分支策略与认证方式；默认不加入自动提交产品功能。

## 11. B34：公开分发、签名与更新

### 现状与目标

当前已有个人使用的 Windows 安装候选，但 P4 和最终干净系统验收未整体完成；未建立正式公开发布、代码签名和自动更新闭环。

### 模块、数据与流程

- `ReleaseManifest` 关联源码提交、依赖锁、固定运行时版本/哈希、许可证清单、安装包哈希、数据格式版本及验收记录。验收与公开下载必须指向同一产物。
- 发布凭据和签名材料由受控发布环境持有，不放源码、普通日志或客户端。依赖固定及干净构建用于核对来源；若声称字节级可复现，另行验证签名/时间戳等差异，不能直接推定。
- `UpdateService` 核对更新来源、渠道、版本、完整性与签名，下载和安装分离。活动任务、未决应用或不兼容数据格式存在时阻止自动安装。
- 升级先保存必要数据迁移依据，记录迁移版本和结果；应用版本回退与用户项目文件恢复分开。旧版本不能读取新数据时，拒绝直接回退并说明可恢复路径。

### 拆期与依赖

| 工作包 | 范围 | 依赖及输出 |
| --- | --- | --- |
| X34A | 发布输入与候选产物可追溯 | P4 候选收口、许可证核对、清单和精确产物验收 |
| X34B | 签名及正式发布 | X34A；发布者身份、签名方案和外部费用已决定 |
| X34C | 用户主动检查并安装更新 | X34B；更新验证、任务阻断和迁移兼容 |
| X34D | 可选自动更新与分批发布 | X34C；失败监测、暂停渠道及回退策略 |

### 验收、失败处理与范围决定

覆盖错误签名、损坏包、非预期渠道、下载中断、安装中断、低磁盘、运行任务、未决恢复和数据迁移失败。更新失败保留可启动的已验证状态或明确恢复步骤，不覆盖用户项目，不静默清空数据。需决定分发对象、发布身份、下载服务、签名成本和更新默认行为；个人使用授权不默认扩展为公开运营。

下表用于一次评审确认方向；批准某行仅确定该项范围，实施开始时间另行明确。所有额度与外部成本均待决，不能从旧开发账本或一次性真实测试额度中默认划转。

| 决策项 | 建议的首个可评审范围 | 待用户决定 | 费用/资源状态 |
| --- | --- | --- | --- |
| B25 文件恢复 | X25A 最近任务整文件撤回 | 是否变更 D02、保留窗口及容量 | 存储容量与开发预算待决 |
| B26 项目范围 | 一个实际常用项目类型 | 规模档位、首个多包/新语言目标 | 工具链、样本和 API 试验额度待决 |

| B28 并发协作 | 队列，再不同项目并行 | 并发上限、多 Agent 是否纳入 | 并发模型预算和本机资源上限待决 |
| B29 外部扩展 | 少量固定只读连接 | 连接器、可写能力、市场是否立项 | 服务订阅和分发维护成本待决 |

## 13. 扩展共用交付门槛

每个获批工作包交付实现、适用验证、首次失败及复测结果、已知限制、迁移/回退说明和对应文档。验证记录绑定代码/产物版本、初始状态、项目类型、模型身份、独立验收入口、人工介入、耗时、请求与工具次数、费用和未知预留；模拟与真实结果分开。

共享前置依赖包括任务身份、持久化操作日志、版本化 IPC/存储、凭据隔离、预算预留和受控应用。只在某个获批包实际需要时扩展它们，不先做无使用场景的通用框架。目录、类型和拆包的具体落点由[总体架构](REMAINING_WORK_ARCHITECTURE.md)与[实施计划](REMAINING_WORK_IMPLEMENTATION.md)统一维护。

当前交付顺序仍是首版阻塞收口与 P4 退出；B25–B34 不作为首版完成的新增条件，也不能因扩展尚未批准而阻塞现有范围的必要修复。任何新范围的通过结论仅覆盖其明确测试矩阵，不承诺任意项目、平台、工具或账号均可使用。
