# DeepSeek 桌面编程助手开发方案

版本：0.8

日期：2026 年 10 月 20 日

状态：P1 在用户已确认的首个可用版本范围内通过，进入 P2 桌面开发；尚无桌面交付或安装包，见 P1_GATE_REVIEW 与 PROGRESS。

先交付一款只接入 DeepSeek 的本地桌面编程助手。优先复用 Codex 开源执行引擎，在实际工具调用验证通过后开发自己的桌面界面。后续新增模型时保留界面与项目管理，只扩展模型接入部分。

## 目标与完成定义

第一版服务已有本地项目、能描述需求并做基本结果判断的个人开发者。优先完成三类任务：理解代码与定位问题；修复可复现的 bug 并验证；实现边界明确的小功能并检查回归。用户选择一个项目，输入需求，软件能够读取相关代码、修改文件、执行测试、根据结果继续处理，并清楚展示修改和执行结果。

第一版完成必须同时满足：核心任务可以使用真实 DeepSeek API 完成；用户能够查看和停止执行；重启后可恢复聊天；模型密钥得到妥善保存；安装包能在目标 Windows 环境独立启动。

用户已明确要求最终外观和布局接近所提供的 Codex 桌面截图，第一版模型来源只有 DeepSeek。界面以该截图为直接设计参考，详见 [界面要求](UI_SPEC.md)。“模型返回聊天文字”“界面看起来像 Codex”以及“测试使用模拟响应通过”，都不足以证明第一版完成，模型能力和任务成功率以实际测试为准。

Git 不是安全边界或备份机制。所有写入都必须满足下文的基线和冲突保护；仅有 `git diff` 不足以保护未跟踪文件或用户已有修改。

2026 年 10 月 20 日 D05 决定：首个可用桌面版本优先支持已验证的 Windows 本地小型单包 JS/TS，随后扩大范围。源码与只读资源合计 16 MiB、单文件 1 MiB、遍历 1024 项；普通预装依赖合计 64 MiB、单文件 16 MiB、遍历 8192 项，复制后以只读方式使用。链接依赖、大型多包、其他语言运行环境与超限项目暂不开放修改，先明确提示。完整依据、首个失败、容量行为及影响见 [项目范围证据](validation/P1_PROJECT_SCOPE.md)。这些边界取代上表中尚待 P1 确定的首个可用版本范围，不改变后续扩展方向。

## 第一次启动到第一次成功

1. 检查桌面应用自身依赖：应用运行时、引擎版本、权限能力、密钥存储是否可用。安装包负责声明或提供这些依赖；失败时明确提示修复步骤，不静默降低隔离。
2. 配置 DeepSeek 模型和本机密钥，说明哪些任务数据将发送给 API。用户主动进行连接检查，该调用计入相应预算。
3. 选择项目，展示真实路径、原生 Windows 或 WSL、实际 shell。检查项目依赖，与应用依赖分开列出。
4. 从 README、AGENTS.md 和项目脚本发现测试命令、运行命令、代码约定与可修改范围，显示来源。缺少或冲突时请用户补齐；不能把文档中的命令视为执行授权。
5. 在应用本地项目设置中保存少量覆盖项：工作目录、测试和运行命令、约定、可修改路径、用户限制。用户设置可以收紧权限，扩大权限必须经实际授权；不新建知识库，不自动改写项目文档。
6. 选择只读分析或修改并验证，展示任务范围和有限的执行预算。写任务先建立基线；无法建立时不开始写入。
7. 完成一个小任务，展示执行过程、文件差异、验证证据和未完成项。缺少测试命令时给出具体下一步，不能用模型的完成声明代替验证。

F01、F02、F03、F05、F06 的联合验收要走完以上路径。修改生效方式采用 D01 最终选择，界面文案与实际行为必须一致。

## 文件改动保护与最小恢复

### 基线与改动归属

开始写任务前，记录受支持范围内文件的存在性、内容基线、哈希与任务标识。快照放在 Agent 不可写的位置，不发送给模型；敏感文件遵守数据边界。Git 索引和用户改动另外记录，任务差异不直接等同于相对 HEAD 的差异。

工具修改前比较当前文件与最近已知版本；shell 执行前保存其获准可写范围的基线清单，执行后核对新增、删除、修改。基线覆盖不到的文件不声称受到恢复保护。测试生成物也属于文件变化，须有明确写入范围与展示规则。

同一规范化项目路径同时只允许一个写任务，重连时不能绕过锁。锁只协调本应用，不能阻止用户在编辑器里修改文件。通过前后哈希、变更事件和操作记录检测外部编辑；出现不一致、链接重定向或归属不明时停止相关写入，保留各版本并显示需要核对。

仅有文件监视或事后快照不能保证无竞态覆盖。P1 必须验证实际编辑工具和 shell 的保护能力；如果直接写路径无法达到要求，应限制命令、转只读或评估隔离副本，不能宣称任意 shell 写入均受保护。P2 开放真实写入前必须解决所选范围内的保护问题。

### 修改何时生效

D01 已由用户于 2026 年 10 月 19 日选择 B：在隔离副本形成提案，审阅后再应用，视图标明“待应用”，应用前重新检查目标文件是否变化。工具修改与 shell 命令统一只写获准的副本，原项目、私有基线与审阅内容不授予 Agent 写权限。实测直接写原项目会覆盖并发用户编辑，首版不采用该方式。

副本需有容量与排除清单；依赖、绝对路径和测试环境差异明确展示，不静默认为与原项目相同。结束并核对进程后冻结提案，审阅内容绑定版本；用户应用的是已审阅的字节，不是随后变化的工作副本。应用时重新核对基线、路径与占用，冲突保留双方；逐文件记录成功、拒绝与需要核对，不承诺跨文件原子事务。应用中断仍须保留基线及操作记录，不能因撤回按钮后置而丢弃未决状态。

### 最近任务的文件恢复

D02 已由用户于 2026 年 10 月 19 日决定首版后置一键撤回。首版仍必须保留基线、差异审阅、应用冲突保护与中断核对，文件恢复可行性结论保留为后续依据。以下恢复边界是后续候选，不属于首版功能承诺：仅恢复最近一个已停止或已结束写任务中有完整基线、可明确归属、当前版本仍等于任务结束版本的普通文件。

若纳入，先展示恢复清单及排除原因，经用户操作后再执行。任务新建文件仅在内容未被后续编辑且归属明确时可删除；删除文件仅在原路径仍空闲时恢复；变更文件仅在版本匹配时恢复。冲突项不自动覆盖，部分恢复必须逐项报告；恢复过程有日志，不修改 Git 索引，不用 reset 或 clean 代替恢复。

完整性检查和恢复之间的竞态、Windows 占用文件、快照容量与清理都需 P1 评估。若需广泛文件系统拦截或复制大型项目，列明额外成本交由 D02 决定。逐块撤销、任意历史回退和复杂 Git 操作仍后置。

停止执行只阻止后续操作；恢复聊天只恢复对话与执行记录；恢复文件需要上述独立机制。外部服务、安装依赖、数据库及任意命令的外部影响不在文件恢复承诺内。

## 权限与任务状态

解释性提问默认使用只读分析；只有明确的修改请求或用户选择才启用修改并验证。只读任务不修改项目或运行可能产生写入的项目脚本；应用自己的必要会话存储使用单独目录权限。修改任务允许在授权范围内连续工作，扩大文件或网络访问、安装依赖等按实际影响处理授权。

授权绑定实际项目、路径范围、操作与任务方式。工具、shell 及其子进程都受执行层约束；命令名字带有 test 不构成授权。项目内指令不能扩大权限，模型收到的权限说明不能替代沙箱或工具检查。只读与修改方式在所选版本中的映射通过 P1 验证。

| 执行状态 | 展示条件 |
| --- | --- |
| 执行中 | 引擎确认任务或工具正在执行 |
| 等待确认 | 有尚未处理的实际授权请求，不能显示已执行 |
| 正在停止 | 已发出停止意图，阻止新调度，等待引擎与相关进程结束 |
| 已停止 | 引擎中断结果与相关进程终止均已核对；不代表文件已恢复 |
| 失败 | 有明确错误导致本轮无法继续，保留已发生改动 |
| 需要核对 | 连接丢失、最后操作结果未知、外部编辑冲突或遗留进程状态不明；不自动重放副作用 |
| 已结束 | 引擎本轮结束且没有未核对执行，不自动等于任务验证通过 |

验证状态另设为通过、失败、尚未验证、不适用。通过须有实际检查证据；失败保留命令和退出结果；无测试通常是尚未验证；不适用只用于该检查与任务无关并说明原因。

界面状态是引擎事实和本地可核对证据的投影，不新增第二套任务成功结论。断线重连后按任务、turn、工具标识读取引擎历史与运行状态，核对遗留进程和文件记录后再继续；具体接口以固定版本 schema 为准。发送停止请求成功不等于已经停止。

每次结束展示五项：完成内容、修改文件、实际验证及结果、未完成事项、下一步。如涉及待应用提案、原有测试失败或部分文件保护，须明确标注。

## 预算与数据边界

开发验证预算覆盖 P1 全部真实请求，用户已于 2026 年 10 月 19 日确定总上限 10 元人民币、单次试验上限 1 元。一次试验中的所有模型请求、自动重试和压缩均计入，不能按每个请求重新获得 1 元额度；跨试验累计不能超过 10 元。应用日常预算按任务独立配置，不能沿用开发阶段总额。预算计量与停止条件落实前不启动真实自动执行。成功率、速度和费用目标在取得基线后制定。

| 限制 | 计数与停止规则 |
| --- | --- |
| 模型请求次数 | 每个实际发出的请求计一次，重试、压缩上下文和连接检查分别计入对应预算；达到上限不再发新请求 |
| 工具轮次与次数 | 一批工具调用为一轮，每个调用还单独计次；多工具响应不能绕过总量限制。达到上限不执行剩余工具，不伪造成功结果 |
| 并发与失败 | 首版有副作用工具串行；记录连续失败次数，同原因反复失败达到限额后停止；不得用新 turn 自动清零预算 |
| 时间 | 设置单命令超时、请求超时和单任务总时长；超时停止新调度并清理关联进程，无法确认则需要核对 |
| 费用 | 本地计量为估算，记录定价日期与来源；未知用量不记为零。发请求前为在途请求预留可估算的最大消耗，无法可靠估算时暂停并提示 |

所有限额由引擎或可验证的调用与工具调度控制点执行，不能仅向模型描述或依赖服务端忽略的参数。若无法约束引擎内部调用，这是 P1 阻塞项。触顶保留结果，用户明确继续时给出新的额度并累计原有消耗。取消可能仍有在途计费；实际账单独立显示或由用户核对，不宣称本地估算等于账单。

项目文件操作和命令在本机执行；提交给模型的提示、代码片段、工具结果和命令输出经 API 发送至 DeepSeek。默认不发送整库，也不启用服务端搜索等额外联网能力。命令联网和模型 API 联网分别授权。

默认禁止 Agent 读取或发送凭据目录、私钥、真实 `.env`、令牌及用户列入的敏感路径；`.env.example` 等样例须确认不含真实凭据才能按普通文本处理。相同规则覆盖搜索、编辑工具、shell 读取、环境变量和命令输出；引擎持有的 API Key 不应传入 Agent 子进程环境。已知密钥和敏感输出在进入模型上下文与日志前过滤，不能只隐藏界面显示。内容识别并非绝对保证，应叠加文件访问边界；若所选引擎没有足够的控制点，作为 P1 架构风险处理。

聊天及必要的脱敏工具记录保存在应用本地数据目录，供恢复使用；普通诊断日志默认只保存错误码、版本、计时与操作元数据，不额外复制源代码或完整请求。诊断导出需预览脱敏内容。设置中提供删除单个会话、全部历史和诊断日志的入口；同步删除相关缓存与恢复快照并说明会失去恢复能力，项目文件不随聊天删除。活动任务先停止并核对，再清理其记录。保存期限与容量上限在 P1 量化后写入配置。

本地删除不代表撤回已经发送的数据，API 的会话存储参数也不代表服务商所有日志均不存在。P1 用合成秘密验证读文件与命令输出的拦截、日志脱敏及删除范围，不使用真实秘密做测试。

## 架构与职责

用户已确认采用 TypeScript 为主要语言、React 与 CSS 编写界面、Electron 提供桌面运行能力。应用按桌面界面、受控 preload 桥接、本地后台、引擎连接模块和独立执行引擎分层；详细职责、计划目录及版本保存规则见 [技术架构](ARCHITECTURE.md)。密钥和工具执行放在本地后台或引擎，界面只通过受控接口发起操作。

```text
桌面界面
  聊天与项目列表、执行记录、差异视图、设置
        ↕
本地应用后台
  引擎进程管理、界面事件转换、凭据、项目设置
        ↕
执行引擎
  首选 Codex app-server
  负责模型与工具循环、会话、执行控制
        ↕
DeepSeek 接入配置或必要的适配模块
        ↕
DeepSeek API
```

界面不直接依赖某厂商的响应字段。若复用 Codex，就由 app-server 管理它已有的会话和工具状态，应用只保存自己的显示与项目设置，避免两套执行状态互相冲突。后续模型扩展通过引擎支持的 provider 配置或适配模块完成；现在只实现 DeepSeek 这一种。

Codex 的官方接入要求包括 Responses 协议、流式事件、连续对话，以及工具调用和结果的匹配。DeepSeek 官方提供 Responses API 文档，但这本身不能证明其所有行为都满足所选 Codex 版本。[Codex 接口要求](https://learn.chatgpt.com/docs/enterprise/gateway-compatibility) · [DeepSeek Responses API](https://api-docs.deepseek.com/guides/responses_api/)

## P1 引擎与 DeepSeek 技术验证

这一阶段先使用命令行或最小测试程序，不做完整桌面界面。在独立临时项目中验证，不能拿用户的重要项目作为首次工具执行测试对象。

### 固定验证环境

先生成一份环境清单：Windows 版本与构建号；原生或 WSL 及发行版；shell 可执行路径与版本；Codex 二进制版本与来源；该版本生成的 app-server schema；应用和样本项目所需运行时；沙箱的实际生效模式及权限；DeepSeek 实际请求模型名和返回模型名、API 地址、协议、推理设置、上下文上限、工具清单、所有预算值、脱敏配置和测试日期。

最初仅观察到 `codex-cli 0.140.0` 及临时目录和 PATH alias 警告。获准开发后，本轮离线试验固定该版本及可执行文件哈希，生成同版本 schema，并在独立配置中完成本地握手；见 [环境与结果](validation/P1_ENVIRONMENT.md)。这仍不是最终产品版本或兼容性通过。当前官方文档可能比该版本新，不能直接照搬配置键或接口，不修改用户全局配置。

候选配置为本地 app-server 的 stdio 连接，以及 DeepSeek 官方 `https://api.deepseek.com` 的 HTTP Responses 接口；模型 ID、完整配置和限额尚未选定。应用到引擎的本地连接与引擎到模型的 HTTP/SSE 连接分开验证。P1 使用独立应用配置目录，不改用户现有 Codex 账户与设置。

执行记录更新：deepseek-flash 最小直接工具往返和 0.140.0 的受限文本链路已实测；其 unelevated 沙箱不能满足项目读取边界。现增加独立目录中的 0.162.0 + MXC 候选，CLI 的部分边界样本通过，仍需该版本的 app-server/模型和临时目录验证。具体证据见 [Windows 验证](validation/P1_WINDOWS.md)，不同版本的局部结果不能合并为 P1 通过。

优先验证原生 Windows 的实际 shell 与有效沙箱，原生不达标才评估 WSL；切换 WSL 的安装、路径、运行时和使用成本按 D03 决定，不能静默降级为无沙箱。官方文档支持原生 Windows 路线，但具体能力依赖系统、版本和策略，不能作为本项目的测试结果。[Windows 沙箱](https://learn.chatgpt.com/docs/windows/windows-sandbox)

### 三类独立验证

每项标记未开始、通过、失败或受阻，并记录实际与预期、证据位置、真实服务或模拟故障。协议、模型能力、本地执行分别给结论，不用一个“兼容”勾选代替。

| 编号 | 验证内容 | 最小通过条件 |
| --- | --- | --- |
| P1 A1 | Responses 流式开始、增量、正常结束、失败、截断、断线 | 不把截断和失败当成功；缺失结束事件转需要核对；同一事件不重复应用 |
| P1 A2 | 连续对话与工具结果关联 | 实际历史回传完整，多个 call_id 正确配对；第二轮能引用前轮结果；不依赖未经支持的服务端续接 |
| P1 A3 | 工具限额和调度 | 模型一次返回多个调用时逐项校验、计数；有副作用操作串行；触顶不再调度；模型请求与自动重试也受限 |
| P1 A4 | 消息角色与关键指令 | 检查实际出站角色映射；任务限制与项目文本不混同；权限由执行层落实。角色差异的行为测试通过，不能仅用“模型答应遵守”作证 |
| P1 A5 | 实际编辑工具和上下文 | 记录实际使用的 function 或 custom 工具；能应用补丁并回传；验证超长输入、压缩与重启历史，不假设服务端压缩可用 |

| P1 B2 | 可复现 bug 与小功能 | 先运行基线，真实模型完成修改，独立验收通过；记录首次失败、修复和人工接管，不承诺任意项目成功 |
| P1 C1 | Windows 环境和路径 | 中文、空格路径下搜索、修改、执行命令正常；实际 shell、依赖与沙箱写入证据清楚 |

A 类参考接口要求与实际请求，B 类参考独立功能结果，C 类参考进程、文件和权限实证。故障可在测试程序注入，但模拟通过不能替代正常路径的真实 DeepSeek 测试。[Codex 接口要求](https://learn.chatgpt.com/docs/enterprise/gateway-compatibility)

停止控制的实测补充：0.162.0 中 turn/interrupt 不足以结束已启动的 unified exec 命令。当前固定样本通过“阻止新调用 → interrupt → 清理线程终端 → 等待引擎终端列表为空并核对进程退出”的流程，见 [引擎工具与停止](validation/P1_ENGINE_TOOLS.md)。清理接口返回与进程真正退出之间继续显示正在停止；这属于 C3 的部分证据，任意进程树和重连仍需验证。

退出标准：真实 API 完成 B 类任务且 A 类通过；C1 至 C4、C6 在所选支持范围内通过；C5 有完整可行性结论，D02 若决定纳入则相关恢复必须通过。D01、D03、D05 中影响真实写入的事项在 P2 前解决。保护或控制点不满足时，P2 不对真实项目开放写入；不能把问题全部留到 P3 或 P4。

当前官方参数差异、来源日期和版本观察集中记在 [评审记录](PLAN_REVIEW.md)；测试前再次核对并冻结实际配置。分项实际证据和剩余门槛见 [P1 核对](validation/P1_GATE_REVIEW.md)，其中的局部通过不改变本阶段退出标准。

P1 退出记录（2026 年 10 月 20 日）：采用固定 Codex 0.162.0、MXC、PowerShell 7.6.5、Node 24.8.0 与 deepseek-flash；需要明确的角色、参数、流事件、预算和串行调度适配，未修改上游引擎。83 项回归、真实任务与独立验收、重启续聊、停止/超时和资源依赖验证通过，D05 已由用户确认。具体哈希与配置见各证据文档。P2 的实际测试继续使用同一开发预算账本和单次 1 元上限，不因为阶段切换重置或扩大授权额度。

首轮验证限定为一轮完整兼容性矩阵和一轮针对失败项的修复复测。仍有结构性障碍时，先形成决策记录，避免无限修改引擎。

路线选择：

- 直接兼容：保留标准 Codex 引擎，用配置接入。
- 差异局部可控：添加范围明确的适配模块，并为流式、工具关联、恢复行为补验证。
- 核心语义不兼容或需大幅修改：列出具体阻塞与维护成本，评估独立实现最小 harness。切换前说明新增工作量，由用户决定重大路线变化。

独立 harness 的必要范围包括工具循环、执行权限、状态持久化、上下文管理和中断恢复，不能把“再写一个循环”当作等价替代。

## P2 完成桌面端的一个完整任务

接上已经验证的引擎，走通首次启动流程，实现两种任务方式、项目与模型设置、实时消息和工具记录、文件差异、确认操作与停止任务。遵守 D01 的改动生效选择；D02 若纳入则实现受限的最近任务文件恢复。

先在用户指定的 Codex 风格布局中完成从输入需求到看到文件改动的完整流程，再按参考截图调整视觉细节。保持左侧项目与聊天、中间对话、右侧文件与差异、底部输入的结构；分栏、标签页及模型区域按 UI_SPEC.md 验收。视觉细节调整不得偏离已明确的界面方向，真实执行路径必须保留。

退出标准：P1 的真实写入门槛已通过；在界面完成一次“修复 bug 并运行测试”的真实任务，能看懂差异是否已经应用、验证结果及未完成项，也能中途停止。覆盖 F01 至 F07 的主要路径；无测试和缺依赖时不能误报成功。完成 UI_SPEC.md 的布局与主要交互对照，模型区域仅显示已验证的 DeepSeek 型号。

## P3 完成恢复与异常处理

完善历史列表、会话恢复、失败提示、请求超时与有限重试、任务预算、上下文管理、数据删除，以及任务中断后的状态核对。核心执行控制已在 P1 验证，这一阶段补齐界面与持续使用场景，不延后安全边界验证。

重试请求与重试工具操作分别处理。网络断开后先核对已完成操作，不能重复执行具有副作用的命令。取消进程时要核对已产生的文件改动和仍在运行的子进程。

密钥使用系统提供的凭据保护机制，日志脱敏；若安全存储不可用，应明确报告，不能静默退回明文。执行范围需要落实到路径校验、权限策略和可用沙箱；将 cwd 设置为项目目录不等于文件系统隔离。

退出标准：F08 和 F09 通过；执行与验证状态映射正确；恢复、拒绝操作、项目外访问、限额、数据清理及取消场景通过，已有用户改动保持完整。文件恢复与聊天恢复单独验收。

## P4 打包与第一版验收

生成 Windows 安装包，核对引擎二进制、依赖、路径与许可证要求，提供简短安装和使用说明。固定发布所使用的版本，避免自动更新依赖后行为发生未经验证的变化。

在无开发依赖的干净环境测试；如果无法提供该环境，必须记录为未完成验收，不以开发机器运行成功替代。

| 场景 | 通过标准 |
| --- | --- |
| 修复已有 bug | 目标缺陷由独立验收确认修复，原先通过的测试不退化；无关的原有失败单列，不强行扩大修复范围 |
| 增加小功能 | 按明确需求改动，功能验收通过且已有测试不退化 |
| 修改后继续追问 | 能正确利用前次结果，不重复执行已完成操作 |
| 停止与恢复 | 停止后不再调度新操作，重启后可查看真实状态并继续 |
| 无效凭据与网络错误 | 提示可理解、界面不假死、不无限重试 |
| 权限边界 | 拒绝后不执行，越界路径与命令遵守执行策略 |
| 保留已有改动 | Git 各种初始状态、非 Git 及任务中外部编辑分别验证；工具和 shell 均不得静默覆盖；冲突明确报告 |
| 审阅与文件恢复 | 区分已应用与待应用；D02 若纳入，新增、修改、删除的可归属文件可恢复，冲突项不覆盖且部分结果明确 |
| 数据与限额 | 合成秘密不外发，历史与快照删除范围正确；预算触顶不再调用，未知用量不记零 |
| 安装运行 | 干净 Windows 环境安装、启动并完成真实任务 |
| 桌面外观与布局 | 安装后按 UI_SPEC.md 与用户截图对照，分栏、标签页、输入区和模型区域符合要求，常用缩放下无关键内容遮挡 |

对理解代码、修复 bug、实现小功能三类任务各进行三次独立运行。每次从规定的同一初始状态建立独立样本，记录原始内容、初始 Git 状态和任务前测试基线，区分原有失败与新引入问题。复测不是新的首次成功，首次失败与修复后结果均保留。

独立验收器放在 Agent 不可写位置，由评审者执行；若只能校验完整性，则记录验收器、测试断言、测试选择和入口命令的哈希，发生改变判为验收无效而不是通过。允许任务需要的正常测试修改，但不能凭修改后的测试证明自己正确；补充独立断言。核对实际执行测试数量与退出状态，防止删测试、放宽断言、跳过或替换命令造成假通过。

记录每次结果、请求和工具次数、耗时、可获得的 token 用量和费用估算，同时记录人工补充上下文、重新解释需求、手工修复、接管的次数及发生阶段。无人干预通过与协助后通过分开报告。

在 P4 增加少量经用户选定的真实任务，使用副本或已经验证的保护方式。观察用户是否看得懂改动、验证与未完成项，能否决定保留或处理结果。恢复快照和删除记录不会自动撤回已发送数据。成功率、速度、费用阈值在 P1 基线后确定，不能凭空承诺或为通过验收事后降低标准。

第一版退出条件：F01 至 F10 均有证据；适用的安全与交互条件全部通过，三类模型任务达到 P1 基线后预先确定的验收阈值，D02 未纳入时明确不提供文件恢复；没有未处理的越权执行、已有修改丢失或取消后继续写入问题。支持范围、局限和人工协助如实记录。测试通过代表覆盖场景通过，不等于任意项目都能自动完成。

## 如何控制开发不偏离

所有工作项都对应功能编号或阶段编号。执行记录始终列明当前阶段、下一步和阻塞。阶段退出标准未达到时，继续解决本阶段问题，不以新功能替代。

每次开发结束只需更新四项：做了什么、怎样验证、尚缺什么、下一步。证据记录实际命令或测试报告位置，并明确真实 API 与模拟测试的区别。

磁盘和测试产物遵守 [开发清理规则](WORKSPACE_HYGIENE.md)：阶段收尾保存精简证据后删除过期副本、重复日志和可再生缓存；必要回归测试继续保留。用户项目、预算账本、未决操作与有效恢复快照不纳入常规清理。清理结果记入执行记录，不把 .gitignore 当作磁盘清理。

范围变更记录原因、对验收的影响和新增工作量；普通实现细节可自主调整，新增厂商、改变主要引擎、增加云服务或显著增加成本需要用户决定。新需求一旦接受，同步修改方案、验收条件和下一步，不能只留在聊天里。

计划以阶段完成条件安排，不在 P1 前承诺固定完成日期。P1 结束后根据引擎兼容性、Windows 执行能力和实际界面工作量给出后续估算。
