# 开发文件与磁盘清理规则

日期：2026 年 10 月 19 日。适用于本产品开发与验证，不授权清理用户其他项目或系统目录。

## 保存与删除边界

| 内容 | 保存方式 | 清理时点 |
| --- | --- | --- |
| 源码、回归测试、少量固定样本、独立验收器 | 随 Git 保存 | 仅在功能废弃且确认没有回归价值时删除；不能为通过测试删案例 |
| 精简验证结论、首次失败、复测、环境与哈希 | 脱敏后写入 docs/validation 和 PROGRESS | 保留可追溯证据，避免每轮复制大段原始输出 |
| 测试项目副本、生成 schema、临时配置和重复数据 | 集中在 .local/runs；旧工具生成的 .local/p1-* 同样受管理 | 相关进程退出、必要结果保存后删除成功运行副本；失败只留复现必需的最小样本 |
| 诊断与原始模型响应 | 默认不保存正文；必要时仅本地脱敏并记录用途 | 问题解决且结论已保存后删除，不进入 GitHub |
| 预算账本、在途请求记录、待核对操作、凭据和有效恢复快照 | 与可清理数据分开，使用 .local/state 等明确目录 | 不按临时文件自动删除；预算账本不能因清理而重置，恢复依据先确认不再需要 |
| node_modules | 活跃工程保留一份，由锁文件重建 | 删除已废弃工程的依赖；不每轮删除活跃依赖造成重复下载 |
| 下载缓存、dist、coverage、旧安装包 | 使用明确的项目目录，缓存尽量在 D 盘 | 阶段收尾清理可重建或重复内容，安装包保留当前待验收/交付版本 |
| 用户原始项目、已有改动、.git 历史、未知来源文件 | 保持原位 | 不作为测试垃圾清理，不用 git clean/reset 代替清理 |

`.gitignore` 只阻止提交，不释放磁盘空间。源码搜索默认排除 node_modules、dist、.local、缓存及生成目录；需要排查时只读取相关的有限内容。

## 执行规则

1. 新的临时运行集中到 `D:\make-codex\.local\runs`，报告和账本分开保存；不改用户全局 TEMP、npm 缓存或工具配置。必要的子进程临时目录仅对该子进程设置。
2. 开始长任务、每个工作包收尾，以及连续开发每约一小时检查一次目录占用。此检查在开发过程中进行，不创建定时任务。
3. 初始开发阈值：可清理运行目录累计达到 256 MiB，或任一工作盘可用空间低于 5 GiB，先停止创建大副本，清理可再生数据并核对剩余空间。阈值是开发管理规则，不宣称已经实现为应用磁盘配额。
4. 删除前核对已解析的绝对路径、用途、大小、进程退出和报告是否保存。目标必须位于明确的任务目录；遇到符号链接、junction/reparse point、正在使用或归属不明的目录，跳过并查明，不跟随链接递归删除。
5. Windows 文件删除统一使用一种执行机制，优先 PowerShell `Remove-Item -LiteralPath`；不拼接跨 shell 删除命令，不对磁盘根目录、用户目录或整个 .local 执行笼统清空。
6. 失败证据先缩减再保留；不因空间限制删除未解决问题的唯一复现依据、首次失败结论或仍可恢复用户改动的快照。
7. 清理记录只写范围、逻辑文件字节数/数量、结果及保留原因。逻辑字节减少不等于操作系统立即释放同等物理空间。
8. 阶段同步前检查实际提交清单：不上传依赖、构建产物、缓存、原始日志、临时项目副本或凭据；必要测试源码和小样本正常提交。

## 当前目录约定

```text
.local/
  runs/       可清理的合成运行副本；有完成标记后再清理
  reports/    本地精简运行结果，可逐步归档/清理
  state/      预算与待核对状态，清理排除
  npm-cache/  项目专用可重建下载缓存
validation/   保留的验证源码、测试和小样本定义
docs/validation/  可公开的精简证据
```

这是开发清理约定。产品自身的聊天、日志和快照删除仍按 DEVELOPMENT_PLAN.md 的数据边界实现，不能把开发清理脚本直接用于用户项目。
