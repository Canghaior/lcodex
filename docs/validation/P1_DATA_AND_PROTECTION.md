# P1：网络、凭据与文件保护可行性

2026 年 10 月 19 日；Codex 0.162.0 + MXC、固定 PowerShell 7.6.5、仅合成项目和本机 HTTP 端点，未调用模型。P1 尚未通过，尤其不能据此开放真实项目写入。

## 出站已知凭据检查补充

后续增加发送前检查：共享 DeepSeek 请求入口拒绝正文中出现当前 API Key；引擎网关同时检查自己的随机认证令牌。检查覆盖序列化请求中的消息、工具结果、工具描述等字段，包括原值、JSON 转义、常见 Base64/URL 编码形式。错误只返回固定代码，不回显匹配内容；在 HTTP 与费用预留之前拒绝。

本地合成测试覆盖普通消息、function/custom 工具结果、Base64 和工具说明，实际 HTTP 调用与账本请求计数均为零；完整回归 46/46 通过。没有用真实凭据做泄露试验。此补充不是任意秘密识别器，分片、其他编码、未知凭据及文件分类仍须依靠读取边界和后续验证，不因此认定 C6 完成。

## 实际引擎观察

| 检查 | 初次结果与处理 | 最终证据及边界 |
| --- | --- | --- |
| 子进程凭据 | 本地随机网关令牌被 shell 继承；真实 DeepSeek Key 始终未传给引擎 | 按同版本 schema 增加 shell_environment_policy.filters 的明确排除后，命令看不到该令牌；不能推广为任意凭据均已过滤 |
| 网络 | 固定 Invoke-WebRequest 请求仅指向本机 canary，显式绕过环境代理，建立正对照 | 启用网络：返回成功且服务收到 1 次请求；关闭网络：命令失败且服务收到 0 次请求。未测所有协议、DNS 或外部网络 |
| 临时目录 | MXC 进程内 TEMP 指向自有 profile/local/Packages/sandbox.../AC/Temp，初始不存在且写入失败 | 预建本次任务的 Packages 根目录并仅授予该子树写权限后，运行时提供有效 TEMP，写入/删除小文件通过；完整项目依赖仍待验证 |
| 用户同时编辑 | 命令读取旧文件后等待 3 秒；父进程写入模拟用户修改，命令随后写回旧内容派生版本 | externalEditWritten=true、externalEditPreserved=false；保护失败。沙箱只控制写入范围，没有比较文件版本的保护，事后哈希不能阻止覆盖 |

网络正对照与禁用样本分别从全新目录开始。凭据过滤修复后两者通过；第一次凭据失败、并发覆盖失败保留报告。固定脚本执行结束、引擎退出后清理；没有真实项目或真实密钥参与上述测试。

配置依据：[固定版本官方 config.schema.json](https://raw.githubusercontent.com/openai/codex/rust-v0.162.0/codex-rs/core/config.schema.json)，ShellEnvironmentPolicyToml.filters 的动作 include/exclude。使用精确变量名，不推断模式语法或所有版本兼容性。

临时目录先验证命令内补建，随后去掉补建命令再次从新目录验证：仅设置私有目录与权限就已存在且可写。该调整纳入有工具的探针配置；重新验证项目只读、外部/敏感读取拒绝、禁网、令牌不可见及中断后进程结束，均通过。未修改用户全局 LOCALAPPDATA 或临时目录。官方依赖追溯到 microsoft/mxc 固定提交 6cd3d58f05d3447e67109cfb75e042803b843ca4；源码阅读用于定位，修复结论来自实际样本，不断言 Windows 内部创建机制已完全查明。

## 隔离候选与单文件恢复试验

新增 file-protection-probe.ts，在 Git 脏工作区和非 Git 样本分别执行：

1. 在外部候选目录修改副本，核对原项目哈希完全不变。
2. 原项目已经出现用户修改时，持独占文件句柄重新读取并校验哈希；版本不符，拒绝应用，保留用户版本。
3. 正常应用期间持 Windows FileShare.None 句柄，模拟的外部写入被操作系统拒绝；完成后文件内容正确。
4. 最近任务的修改文件仍匹配任务结果时，使用相同锁与版本检查恢复原内容。
5. 后续又有用户改动时，拒绝恢复；Git 索引、既有用户笔记和独立验收器保持原样。

以上两种样本均通过。试验是受信任协调程序持锁，不把受信任权限开放给模型命令，也不是新增产品的完整写入接口。它证明普通小文件上可以缩小“检查后再写”的竞态；尚未处理创建/删除恢复、链接与路径替换、崩溃恢复、多文件一致性。写入途中进程崩溃仍可能留下部分内容，必须保留基线和待核对记录，不能宣称已有原子事务。

本样本原文件 104 字节、候选 124 字节，只足以验证行为，不足以制定真实项目的复制速度或容量阈值。实际副本、快照、依赖处理及清理必须继续量化。

## D01 写入方式：供用户决定

| 选项 | 用户体验 | 实现影响 |
| --- | --- | --- |
| A 直接写原项目 | 授权后改动立即落盘，审阅的是已发生改动 | 当前任意 shell 写入无法保护并发用户编辑；需要限制写命令或增加统一受控写入层。不能靠“请用户别编辑”满足已有保护要求，工作量较高且实现路线仍有风险 |
| B 隔离副本形成提案，审阅后应用（建议） | 任务执行期间原项目不变；用户查看差异后应用。冲突保留双方版本 | 模型与 shell 只改副本；应用/恢复经过可信协调程序。增加复制时间与磁盘占用，需要容量上限、依赖策略、路径说明及应用异常处理；小样本已有可行性证据，完整能力仍待实现 |

这会改变 F05 审阅交互与磁盘占用，因此按既定 D01 留给用户决定。P1 中的可行性试验不等于默认选择 B。D02 最近任务恢复仍待创建/删除、崩溃与容量证据后决定；不提前承诺完整撤销。P0–P4、DeepSeek 单厂商和主引擎候选均不改变。
