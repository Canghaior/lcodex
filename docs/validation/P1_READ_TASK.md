## 约束与适配范围

仍保留引擎生成的历史与角色；当前入口仅把一个 exec_command 定义发给 API，第二轮禁用工具。模型得到明确的单次读命令、shell、目录和 JSON 答案格式。此结果证明受限链路和该诊断样本，不证明模型自主选择复杂命令、多文件定位或角色优先级已满足要求。

实际引擎仍发 parallel_tool_calls=true；入口改成 false，但不依赖服务端遵守。先缓冲完整真实 SSE，再检查所有工具 item 和参数增量与最终结果一致，只接受一个指定读命令；扩权、额外命令、未知工具、多调用及冲突的提前流式调用均拒绝，不向引擎转发。文本探针也使用相同检查，不能只看最终 response.output。缓冲会影响实时性，属于 P1 受控入口，尚未作为产品交互定案。

源代码内容只来自合成项目。只读 scope、敏感路径拒绝和子进程环境继续使用已有约束；全目录内容哈希相同。此次没有 API 重试、人工改代码或修改任务答案；主助手制定了狭窄工具合同和验收格式，不能将此记作无人工限定的成功率。

真实试验时请求大小上限为 32 KiB，但观察到两轮引擎原始请求均小于 13 KiB、过滤后更小，因此提交版本保留原有 16 KiB 上限，没有扩大输入或费用额度。两轮输出各限制 1024 token，仍用同一持久预算账本，每轮预留 0.25 元，同一试验不重置 1 元上限。
