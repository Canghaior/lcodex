## 角色与实际证据

[DeepSeek 官方 Responses 文档](https://api-docs.deepseek.com/guides/responses_api/) 说明 developer 按 user 处理。固定引擎实际发出的前两条消息为 developer，其后项目与任务内容为 user。因此在已认证的本地引擎入口，将 developer 消息映射为 system，其余消息和工具 call_id 保持原样；不修改引擎原始历史，不根据项目正文自称的身份提升权限。

这只是该引擎与 DeepSeek 的兼容适配；多个高优先级消息的复杂冲突、压缩后语义和所有提示注入情形尚未验证。角色不承担文件、命令或网络安全边界，执行权限仍由独立入口与 Windows 沙箱限制。

两个颜色样本只提供有限行为证据，不证明抗提示注入能力。只读任务在新的独立合成项目中开始，文件哈希保持不变；引擎与历史均为 completed，进程正常退出，收尾 32 毫秒。请求记录核对 developer→system、user 不变、function_call/function_call_output 保持关联。此轮没有修改真实项目。

## 预算和验证范围

允许每请求输出限制在 1–1024 内设置，以便验证截断；没有提高原来的最大输出或预留额度。非法、缺失、非整数及超上限值在 HTTP 前拒绝，收到的用量超过请求限制时保留计量并报告违反限制。
