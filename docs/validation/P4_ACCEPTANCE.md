## 方法

`tests/packaged-live.mjs --live` 启动真实发布 EXE、真实 app-server/MXC 和捆绑的 Node/npm，通过 DeepSeek 官方 Responses API 完成任务，不模拟模型响应或工具结果。测试器在真实 HTTP 入口外叠加原有开发预算账本，每次请求仍只发送一次；应用个人预算同时工作，开发累计 10 元、每次试验 1 元不因新配置或换阶段重置。

API Key 通过隐藏终端输入及受控 IPC 使用，在测试配置中由 Windows 加密保存，不进入命令行参数、环境变量、报告或仓库。发布包内没有测试注入入口；仅测试器通过 Playwright 的主进程调试能力附加开发预算统计。

每次新建规定初始项目，提前运行外部独立验收器：bug 初始 1/8，小功能初始 1/7。验收器不在模型可写目录内，在只读 MXC 中采集函数结果，协调程序检查断言和完整性；应用前核对原项目不变，应用后再次验收。修复可增加相关回归测试，不能修改无关用户文件或依靠修改项目断言冒充外部验收通过。只读任务需实际读取文件，核对具体代码原因和计算规则，不把静态诊断标为已执行测试。

原因是原 48 KiB 上限计算整个发送请求，包括指令、工具定义、历史与工具输出；多个必要源码片段累计后超出。桌面现显式采用 96 KiB，原 P1 的 16/48 KiB 探针窗口保持。每次 0.25 元预留、1024 输出 token、最多八次请求、单试验 1 元和累计 10 元不变；超限在 HTTP 前拒绝，不默默截断上下文。按已复核的峰时输入 2 元/百万 token、输出 8 元/百万 token，以 98304 个输入 token 保守估算约 0.2048 元，仍低于原预留；返回用量继续受 100000 输入 token 及预留金额上限检查。
