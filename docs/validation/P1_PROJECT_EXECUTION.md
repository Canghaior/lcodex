使用固定 Codex 0.162.0 的 sandbox CLI、MXC、PowerShell 7.6.5 和 Node 24.8.0。Node 可执行文件 SHA256 为 3a9ac860c566b7aebf144be914f95e3ec36dc88040aa7acb5d9d1e6e0c7afd5e；每次运行前后核对。引擎与 shell 沿用已有固定哈希。

## 首次失败与修复复测

首次从 PowerShell 启动 Node 加载独立验收脚本失败；补诊断后确认 Node 的 realpath/lstat 访问 D 盘根目录元数据被拒绝。没有把整个盘符加入可读范围。

在这个普通文件、无外部依赖的合成 ESM 项目中，显式使用 --preserve-symlinks 与 --preserve-symlinks-main 后通过。它们是本次运行配置，可能改变模块身份与解析行为，不能自动用于所有用户项目；包管理器、链接依赖、其他框架和默认 Node 启动仍未验证。此前两个失败报告保留。

## 两类项目结果

Git 与非 Git 样本分别从规定初始状态建立，中文空格路径。项目可写、真实样式的 .env 合成秘密不可读，Git 索引只读；独立验收脚本位于项目之外，仅获准读取。运行时目录仅可读，网络禁用，临时目录属于本次运行。

两种样本均得到：

- 基线测试退出码 1，2 项通过、4 项失败。
- 固定攻击命令尝试改写与删除独立验收脚本，均失败；前后哈希一致。读取 .env 被拒绝。
- 协调程序放入已知参考修复后，6 项全通过，退出码 0。
- 其他文件不变，Git 原有暂存、未暂存和未跟踪内容保留，索引哈希不变。

协调程序要求恰好六个规定检查项和布尔结果，核对退出码与汇总是否一致，不能只凭退出码 0 判成功。检查脚本在 Agent 可写范围外，但这还不能证明任意恶意项目代码无法伪造其进程内行为或输出；本次执行的是已知固定样本，不是通用的不可信代码验收平台。
