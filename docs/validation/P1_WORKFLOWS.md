# P1 一般多步任务与限额

2026 年 10 月 19 日，对应 A2/A3、B2、C6。固定 Codex 0.162.0、PowerShell 7.6.5、Node 24.8.0、deepseek-flash，原生 MXC。不是完整产品验收。

## 从受限单补丁到多步任务

新增 workflow-probe：给模型任务描述、项目位置和运行环境，不提供完整源码、精确补丁或算术表达式白名单。模型自行读文件、修改、执行测试和总结；工具请求仍经过流事件一致性检查、路径/参数检查和实际 OS 沙箱。执行范围仍为隔离副本，普通 shell 不通过字符串关键词判定权限。

只允许固定 shell、隔离项目 cwd、不加载登录配置、无提权与网络；允许项目内相对或绝对补丁路径，拒绝越界、敏感文件、Git 元数据及局部引擎配置。副本排除 .codex/.agents，并在执行层拒绝这些目录，不能让项目配置自行开启 hooks 或插件。AGENTS.md 普通说明仍可按项目根读取。

独立验收在模型不可修改的协调程序中计算期望值。沙箱里的只读 runner 只返回候选函数的实际输出，协调程序逐项比较；不接受“测试通过”文字或候选代码生成的断言结论。bug 样本含随机输入，项目已有测试与独立验收分别记录。每次重新创建规定初始项目，保留初始失败。

## 限额与故障实证

P1 多步任务初始值：模型请求最多 8 次，工具最多 12 次、工具轮次最多 8，连续失败 2 次停止，总时长 180 秒、命令截止 45 秒。最初仅接受每响应一个调用；10 月 20 日受控串行入口已通过下述实际引擎批次检查。限制值不等于产品最终默认，新入口的真实模型任务仍需复测。

限额事件 fsync 后才调度，重连不能清零；未知工具结果不自动重放。实际 app-server 配合模拟响应验证：8 次请求/8 个工具后拒绝第 9 次新调用；两次实际 exit 1 后拒绝下一次调用。两例任务按失败结束、引擎正常退出、原项目未变，不展示可应用提案；验证器的通过仅表示“限额正确触发”。时间/时钟回退有组件测试，命令截止的完整进程树实证仍需补充。

为多步历史明确启用最多 49152 字节请求正文，旧探针继续默认 16384 字节；输出仍最多 1024 tokens，每次真实请求预留仍为 0.25 元。超限在 HTTP 和预算预留之前拒绝，单次试验仍共用 1 元上限，全部试验共用原有 10 元账本。

## 未完成项

### 多工具批次组件补充（已接入验证入口，实际联测受阻）

新增 serial-response 组件：完整检查所有调用及其流事件后才放行首项；对交错事件按原输出项归组，保持调用标识、参数与最终输出，重编号流序号；后一工具等待前一工具的实际完成回报。暂停/取消、未知完成、违规的后续调用都不能触发剩余操作。当前上限每批四项，整个批次须先通过范围和总量检查。

TaskLimits 现在分别保存批次轮数、待调度队列和每项结果；有未知或待调度批次的重启进入需要核对，不自动继续。验证记录版本升为 2，旧验证格式拒绝读取；真实预算账本格式和累计金额不变。

新增五项组件测试涵盖混合调用的串行释放、标识/参数/增量不一致和隐藏调用、等待期间取消、未完成批次重启不重放、每项次数与批次轮数独立限制。与旧单调用和限额回归合计 12/12 通过；首次 TypeScript 断言重载错误已修复。随后加入 ToolResponseGate 并接入 workflow-probe，实际完成事件需匹配调用标识、类型及确定退出结果；重复完成不重复计数，未知退出不放行下一调用。新增组件用例通过，实际引擎联测尚未成功执行，不能将这些结果当作 A3 已通过。

新的 --serial-batch 探针安排两个有先后依赖的模拟命令，检查开始/结束事件顺序及下一轮两个 call_id 的结果关联，再走原有补丁和独立验收。所需实际 MXC 执行请求的自动审批超时；尝试在更受限环境运行时，基线阶段返回 native MXC is unavailable on this executor，模型请求数及工具数均为 0。没有更换沙箱或放宽权限，没有新增 API 消耗。应在审批恢复后的原生执行环境重跑本探针，再用真实 DeepSeek 任务复测新入口。

所选版本的 [上游工具调度实现](https://github.com/openai/codex/blob/rust-v0.162.0/codex-rs/core/src/tools/parallel.rs) 按工具能力使用不同的并发锁。因此仅配置 parallel_tool_calls=false 不作为本项目的串行执行证据。等待流内工具完成回报是否会与引擎状态衔接正确，仍须实际联测，不根据源码推断直接放行。

审批恢复后，完整 `npm test` 80/80 通过、无跳过。`workflow-probe ... bug --serial-batch` 通过：模拟模型四响应、实际工具四次、三轮；两条命令依次报告 started/completed，第二条命令实际读取第一条写出的标记；下一轮历史中两个 call_id 各有一条工具结果。再经实际补丁和项目测试，外部独立验收 1/8→8/8。原项目不变，引擎退出码 0，成功副本清理。批次标记作为合成项目提案中的新增文件如实记录，未应用到产品仓库。
