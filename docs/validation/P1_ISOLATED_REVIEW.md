# P1 隔离副本与审阅应用

日期：2026 年 10 月 19 日。对应 F05/F07、P1 C4/C5。用户已选 D01 隔离副本审阅后应用，D02 首版后置一键撤回。本文记录局部实现证据，不代表 P1 通过或桌面产品已经实现。

## 实现边界

- TypeScript 协调组件创建项目写锁、私有基线及独立工作副本；敏感路径、Git 元数据和 node_modules 明确排除，不复制真实凭据或共享可写依赖链接。
- 结束并确认进程后才能冻结审阅。冻结内容与 review ID 绑定，应用取冻结字节；工作副本在审阅后变化不会悄悄替换用户批准的版本。界面尚未实现，目前由合成测试显式调用审阅和应用。
- 应用前保存逐文件 intent，完成后保存结果，均 fsync。没有确定结果就保留锁和状态、停止后续应用，不自动重放。首版后置撤回不意味着可以删除基线或未知操作记录。
- Windows 原生辅助验证程序经固定 PowerShell 7.6.5 加载，用文件句柄读取属性与哈希，拒绝 reparse point 和硬链接。普通 UTF-8 文件可形成改动，二进制资源只允许有界复制并保持原样。应用时持有父目录链与文件句柄，避免检查后路径重定向或用户并发写入；新增使用 CREATE_NEW 拒绝占用路径。
- 本轮仍是 P1 的有界组件：每文件 1 MiB、总计 16 MiB、清单 1024 项、剩余空间至少 5 GiB。新增文件可在持有父目录链句柄时创建缺失目录，遇到链接或占用则拒绝。这些容量值是试验限制，不是已经决定的产品支持范围。

## 已有实测

六项 Windows 组件测试通过：

1. 非 Git 与已有暂存/未暂存/未跟踪内容的 Git 样本：副本修改不影响原项目；冻结后再改副本仍应用已审阅内容；新增、修改、删除和并发冲突分别正确处理，索引与敏感文件不变。
2. 在哈希核对与写入之间尝试外部写文件、改名父目录和改名项目根，均被持有句柄阻止，随后正常应用。
3. 已占用新增目标、junction 重定向与硬链接被拒绝，外部哨兵保持原样。
4. 副本中的新增敏感文件及二进制内容拒绝冻结，原项目不受影响。
5. 空文本文件可新增与修改；路径穿越、ADS、Git 元数据与 Windows 设备名被拒绝。

首次失败保留：PowerShell stdin 默认编码导致中文路径无法打开，显式 UTF-8 后修复；PowerShell 到 .NET 的空字符串转换使新增误走 OPEN_EXISTING，改为明确 createNew 布尔值后通过。普通宿主沙箱禁止创建 junction，相关完整测试在已授权的真实 Windows 环境执行，没有跳过此检查。

## 仍需验证

仍需完整容量回收、更一般项目依赖与真实任务重复性、写入途中断电的完整核对流程。写入普通文件当前使用持锁原位写入，断电可留下部分内容；持久记录用于发现未知结果，不构成自动恢复或跨文件事务。

捕获及应用组件不应直接向界面或模型暴露任意路径接口。节点调用方必须确认引擎及相关进程结束，正确映射审阅权限，并阻止模型写私有目录。完整 P1 门槛见 [核对表](P1_GATE_REVIEW.md)。

参考：[Microsoft CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) 的共享方式、创建方式及 reparse flags；[GetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfileinformationbyhandle) 的句柄属性。上述文档说明 API 语义，实际保护范围仍以试验为准。

## 实际引擎接入与中断补充

Codex 0.162.0 app-server + MXC，模拟模型响应，真实补丁与 shell 执行：副本修复 → 独立 Node 验收 6/6 → 查询后台终端为空 → 引擎正常退出 → 冻结差异 → 合成用户审阅确认 → 应用原项目。原项目在应用前哈希不变，最终仅 invoice.mjs 改变，退出 30 毫秒；没有真实 API 请求或桌面界面。

同一 shell 中的主动边界尝试：原项目读/写、私有基线读/写、根标记写入均失败；副本正常读取成功，补丁修改与测试成功。私有目录使用显式 deny，根标记只读。此样本证明这些实际调用的拒绝，不泛化为任意子进程或文件系统攻击均已验证。

首次两次接入在 thread/start 加载 AGENTS.md 时访问拒绝，无模型请求。仅调整私有目录权限仍失败。原因与非 Git 副本向祖先查找项目根有关；加入每任务唯一的私有副本根标记并设置 project_root_markers 后通过，未扩大原项目或基线权限，未初始化用户非 Git 项目。根标记不进入原项目差异，冻结前核对未变化。配置依据见 [Codex 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

中断补充：新增文件经 CREATE_NEW 创建空文件后，测试协调程序在写入前取消确认。实际留下空文件，记录 needs-reconcile，拒绝正常关闭与新任务。协调进程结束后，独立读取持久 intent/result，并与当前内容比较为 diverged；冻结候选仍保留，未重放写入，项目锁仍要求核对。只读核对器分别区分与基线一致、与目标一致及偏离，任何观察都不自动授权重试、释放锁或丢弃基线。

本补充不是断电或写入中段崩溃恢复通过。之前原位写入会留下部分内容的失败结论仍有效；首版仍不提供一键撤回。

## 写入中段退出与资源文件补充

新增实际进程中断测试：将 256 KiB 文本的前半部分写入并 Flush(true)，在受控测试检查点终止原生写入辅助进程，再令协调进程退出，确保未写 result。独立检查进程观察到“前半新内容、后半旧内容”，读取持久 intent 判定 diverged / needs-reconcile；完整原始基线和完整候选均仍存在，项目锁拒绝新写任务，文件没有被自动重放或回滚。测试通过。此证据覆盖确定性的进程退出，不冒充物理断电或一键恢复验证。

测试首次构建遇到 TypeScript 对类方法内闭包的参数类型收窄问题，修正后可运行；首次运行因测试辅助 PowerShell 的 stdin 未设置 UTF-8，未抵达写入检查点。显式设置编码后复测通过。普通 JSON 应用桥不开放测试检查点。

资源文件：capture 记录 text/binary，二进制资源原样复制并标为 readOnlyAssets；删除、变更为其他字节/文本、增加新二进制文件均拒绝冻结。实际组件样本通过：资源保持原样时可以审阅和应用 README 文本修改；资源字节不变。补丁入口对相对、绝对及 Move to 路径均拒绝只读资源。workflow 的 MXC 配置已生成资源 read 规则，但本轮引擎联测受环境阻塞，不能据此认定 shell 的资源只读验证通过。

应用新增最终句柄路径核对，拒绝规范路径与实际打开路径不同的别名，依据 [GetFinalPathNameByHandleW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew)。普通中文路径与句柄测试通过；本轮没有可声明的 8.3 短名实测证据。

本轮最新 80 项回归中 76 项通过，四项 junction 场景在受限执行环境创建链接时受阻；其中写锁样本的清理曾用 ENOENT 遮盖原始错误，已改为只清理实际创建的链接。完整环境中的复测仍待自动审批服务恢复，不将旧版本的完整通过结果代替本节点检查。
