## 固定组合与交付边界

应用版本 0.0.1，Electron 44.9.0、electron-builder 26.15.3、Codex 0.162.0、PowerShell 7.6.5、Node 24.8.0、npm 11.6.0，Windows x64。保持 D05 小型单包 JS/TS 范围和原生 MXC；应用运行时随包提供，用户项目的第三方依赖、外部服务仍由用户事先准备。

`scripts/package-windows.mjs` 只收集实际入口可达模块和渲染资源，检查 ASAR 文件白名单；不打包测试、个人设置、截图参考、原始日志、开发账本或凭据。运行时清单当前 2916 个文件，启动时核对完整清单、哈希、链接与关键可执行文件固定哈希。此校验用于发现缺失、误打包和损坏，不替代 Windows 代码签名。

## 首次失败与修复

| 首次观察 | 处理与复测 | 证据边界 |
| --- | --- | --- |
| 测试器替换系统 USERPROFILE/APPDATA 后，Electron 在创建窗口前无法获得用户目录 | 保留 Windows 已知文件夹语义；使用显式、已存在且非重定向的 `--user-data-dir` 测试配置。同步 CommonJS 入口保留 pre-ready 初始化 | 这是测试环境问题；真实默认配置仍须安装验收 |
| builder 默认过滤掉捆绑 npm 的嵌套 node_modules | afterPack 按固定运行文件清单复制，启动全量核验；ASAR 另用严格文件白名单 | 修复后完整 2916 文件清单通过 |
| 对数千个小文件逐一异步流式计算哈希导致窗口超过测试等待时间 | 小文件同步读取计算，大文件继续流式计算；不取消完整核验 | 发布程序启动、配置、重启通过；不外推任意磁盘速度 |
| npm 在 MXC 内启动后 45 秒无输出，命令限额触发并保留需要核对 | 对照：普通环境 npm 正常，MXC 直接 Node 测试正常；关闭 npm 自动启用的 Node 磁盘编译缓存后正常。后台固定 `NODE_DISABLE_COMPILE_CACHE=1`，未扩大文件权限 | 保留首次失败；正常 `npm.cmd test` 完整复测通过。底层缓存阻塞机制未进一步断言 |
| 诊断脚本误把 Electron evaluate 的第一个参数作为命令字符串 | 修正测试器参数位置 | 原检查在执行前拒绝；不是产品允许了无效命令 |
| 安装测试器按不带版本的名称查找卸载项、以默认编码读取中文路径、误用 IPC 的 error 字段 | 按实际版本化名称与精确安装路径核对，固定 UTF-8 输出，使用 code 字段；复用自己已安装的实例继续测试 | 这些均为测试器失败，产品拒绝与实际安装没有被改为假通过 |

## 后续真实模型验收的预定口径

以下为运行前固定的条件。现已执行并取得修复后 9/9，完整过程见 P4_ACCEPTANCE，条件不因结果而降低。

基于 P1 已完成一次修复后的三类能力、bug 8/8 与功能 7/7 基线，P4 固定为三类各三次独立运行。每次创建规定初始项目，不借用前次修复结果；读取任务核对源码依据和诊断事实，修改任务由 Agent 不可修改的独立验收器判定，并复核用户原有文件。

这组受控小样本要求 9/9 达到对应任务标准、零人工补丁/接管；任何首次失败保留并单列修复复测，不能把复测替换首次结果。沿用已验证的 180 秒任务、45 秒命令、8 次请求等停止限制及用户既定每次 1 元、累计 10 元开发预算，不另作速度或通用成功率承诺。记录实际时长、费用、补充上下文和接管次数。测试不通过时继续修复或明确限制，不能事后降低本组标准。

少量经用户选定的真实任务、用户对外观与审阅的实际反馈，以及干净 Windows 安装和真实任务，是另列的交付门槛。合成项目、模拟模型、当前开发机安装均不能替代这些证据。
