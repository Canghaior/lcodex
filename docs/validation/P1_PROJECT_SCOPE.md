# P1 项目依赖、资源与范围证据

2026 年 10 月 20 日，对应 C1/C2/C4/C6 和待定 D05。这里区分已经验证的范围与完整产品承诺；P1 的技术样本不能自行把最终产品缩减为只支持小项目。

## 当前实现与结果

隔离协调器对项目源码/资源保存独立基线。根目录已安装的普通 node_modules 另行捕获并复制，不指向原项目、不共享可写缓存、不安装软件包或执行包脚本。捕获使用相同的 Windows 句柄、重解析点/硬链接/最终路径检查；依赖中的敏感排除项导致明确拒绝，不把不完整依赖当成可运行环境。

依赖目录在实际 MXC 中只读，不能成为补丁目标。封存提案时再次检查依赖清单与每个内容哈希；变化、删除或新增均拒绝封存。提案只包含原项目可审阅的普通文本变化，不包含 node_modules 或二进制改动；验证位置仍为隔离副本。

新增两个原生组件测试通过：2 MiB 依赖可复制和校验，源文件修改可审阅应用而原依赖保持不变；候选依赖被改写则拒绝。超过源码单文件/依赖单文件上限以及依赖内敏感文件均在生成可应用提案前拒绝。

`workflow-probe ... bug --resources` 使用本仓库已安装的 TypeScript 5.9.3（没有下载），复制 132 个编译器文件、23625066 字节，另加三个合成依赖文件和二进制资源。在固定原生 MXC 中：资源可读，资源与依赖普通写入拒绝；TypeScript 严格 noEmit 检查实际解析本地依赖类型，项目测试运行成功；外部验收 1/8→8/8，仅 src/catalog.mjs 进入提案，原项目完整保留，引擎正常退出。模拟模型四响应、三个实际工具，无付费调用；成功副本清理。

首次资源探针包含删除/重命名，被引擎命令策略在启动前整条拒绝。该拒绝没有发出 commandExecution 完成通知，入口等待至 45 秒上限后停止并保留待核对状态。引擎持久记录含 blocked by policy，回读历史为 interrupted、无命令项；不得把此结果当成操作系统已分别验证删除和重命名。后续样本移除这两项，不以其他写法重试被拒操作，仅验证正常读写边界和编译。此类启动前拒绝的即时呈现仍有限制：目前保守超时，不误报执行成功或重放。

## P1 已实现的容量上限

| 类别 | 当前验证程序的边界 | 超出时行为 |
| --- | --- | --- |
| 源码与资源 | 合计 16 MiB、单文件 1 MiB、遍历 1024 个文件/目录项 | 捕获或封存拒绝，不生成可应用提案；根标记和新增文件也占空间，不能把初始恰好满额视为可增长 |
| 已安装普通依赖 | 合计 64 MiB、单文件 16 MiB、遍历 8192 项 | 明确拒绝；不自动安装、删减依赖、跟随链接或放宽权限 |
| 工作盘 | 准备副本前至少剩余 5 GiB | 停止准备，提示清理；不能删除用户项目或未决恢复状态 |
| 可清理测试数据 | 达到 256 MiB 时先检查和清理 | 按 WORKSPACE_HYGIENE 的归属/进程/链接规则；不清空 .local/state |

容量是本轮小型样本的可执行防护边界，不是大型仓库性能承诺或产品长期限制。生成物、依赖快照和 JSON 基线占用与源码体积不同；不能将上述源码上限当成总磁盘占用上限。源码 8 MiB 的此前复制/哈希实测仍见 P1_RECOVERY；当前编译器约 22.5 MiB 的复制和真实运行补充了依赖路径。

## D05：进入桌面阶段前的范围选择

已经验证：Windows 原生、小型单包 JS/TS、普通 UTF-8 源文件、Git 和非 Git、中文空格路径、已有用户改动、无外部服务的测试，以及上述普通预装依赖与只读资源。

尚未验证：链接型依赖（例如含链接的 workspace/pnpm 布局）、大型多包项目、超出容量边界的仓库、其他语言运行时与外部服务。不能把一个语言的成功推广为 Codex 的全部项目能力。

选项一：把已验证范围作为首个可用桌面版本的明确边界，超出范围提示且不开放修改，后续按真实需求扩展。收益是可立即进入已授权的 P2；代价是首版不能用于很多大型或其他语言项目。

选项二：先选择更大的真实项目或其他语言环境扩展 P1，再进入 P2。收益是更早满足更广的实际用途；需要额外运行环境、依赖复制/存储优化、权限与任务测试，桌面交付相应后移。

该项影响用户最初希望的通用编程能力，已按 DEVELOPMENT_PLAN 的 D05 和 AGENTS.md 交由用户决定。2026 年 10 月 20 日用户明确选择“先做已验证范围的桌面版，后续扩展”；选项一成为首个可用版本边界，后续扩展不取消最初的通用产品方向。超出范围时明确提示，不静默降级安全策略或承诺未经验证的写入。
