日期：2026 年 10 月 19 日。依据：开发方案 0.5 与已确认的技术架构。用户已授权开始开发，并将当前方案和后续完成的小阶段同步到 GitHub；不设定时任务。

## 目标与执行顺序

在本仓库开发 TypeScript + React + CSS + Electron 桌面应用，第一版只接 DeepSeek，外观和主要布局遵守 UI_SPEC.md。引擎首选 Codex app-server，兼容性通过后才进入桌面应用实现。

执行顺序：P0 文档与版本基线 → P1 环境、最小验证程序与真实兼容验证 → P2 桌面完整任务 → P3 持续使用与异常恢复 → P4 安装与验收。各阶段完成条件优先于时间安排，不先承诺完成日期。

## 代码组织与检查方式

P1 只按需建立最小验证程序、样本和报告，不先创建完整 Electron 空工程。验证程序放在 `validation/`，可公开的脱敏结论放在 `docs/validation/`；这两个目录已随首轮本地通信验证创建。包含本机路径、原始响应或凭据的临时数据放在被忽略的本地目录。真正的隔离和验收器保护必须通过实际权限验证，不能把 `.gitignore` 当安全措施。

P2 再按 ARCHITECTURE.md 建立 `src/main`、`src/preload`、`src/renderer` 和 `src/shared`。从验证程序提取经过验证的连接代码，避免同时维护两套执行逻辑。第一版不自建云端后端、不重新训练模型、不提前加入其他厂商。

每个工作包完成时：

1. 对照功能编号和完成条件检查实际改动。
2. 执行适用检查：文档检查；代码的类型检查、相关行为测试和需要的构建；涉及引擎时另记真实或模拟环境。具体命令在工程建立后写入 README，不提前伪造可运行命令。
3. 检查 diff 和提交文件，排除凭据、原始日志、依赖、产物与无关改动；已有历史也属于首次公开检查范围。
4. 按 WORKSPACE_HYGIENE.md 检查占用、保存证据并清理已结束的临时运行；更新 PROGRESS.md，列出完成内容、验证证据、清理结果、问题和下一步。
5. 建立范围清楚的本地提交，推送后核对远程提交 ID。工作包可分多次提交，但阶段通过只能依据验收结果。

没有实际通过的项目保持未验证或失败，不用“代码已写完”“界面可打开”替代功能完成。
